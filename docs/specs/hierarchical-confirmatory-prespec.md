## 0. v1.6 — 게이트 미통과 뒤 사람이 실행을 결정했다 (2026-09-23)

깊이 확장 파일럿은 게이트를 통과하지 못했다.

```
D(42) - D(18) = -0.119 [-0.238, +0.079]   자격 unit 5
D(18) = +0.109  ->  D(42) = -0.010
```

§6 의 규칙은 "0 포함 -> 확인되지 않는다. 확증 코호트 실행 여부를 사람이
판단한다. 자동으로 돌리지 않는다" 이고, 그 판단으로 **실행하기로 했다.**
근거는 파일럿의 표본이 작아(주 비교 8 unit, 깊이 5 unit) 작은 양의 효과를
배제하지 못한다는 점이다.

**그러므로 이 코호트의 목적이 바뀐다.**

```
원래   효과 검출.  D = 0.118 을 가정해 검정력 79% 로 설계했다.
지금   구간 축소.  깊이 42 에서의 최선 추정은 D = -0.010 이므로
       "검출" 을 기대하지 않는다. n=5 에서 폭 0.32 인 구간을
       n~19 에서 0.17 수준으로 좁혀 **효과의 상한을 말하는 것**이 목적이다.
```

따라서 결과 해석도 바뀐다 — 음성이 나오면 "효과가 없다" 가 아니라 **"있어도
관측된 구간보다 작다"** 로 쓴다. §7.0 의 적응적 사이징 공식은 D_p > 0 을
전제하므로 **적용하지 않는다.** 가용한 34 표적을 전부 쓴다.

## 1. 가설 — 하나다

> warm-up 에서 확인한 백본 간 성공률 차이를 이용해 좋은 백본에 folding 을
> 집중하면, 후보 깊이가 충분할 때 서열 순위화만 쓰는 것보다 joint-pass 를
> 더 많이 회수하는가?

이 가설은 `35_`/`36_` 의 **사후** 결과에서 나왔다. 거기서는 `greedy_frozen -
rf_only = +1.55 [-0.60, +4.25]` 로 0 을 포함했고, 그 +1.55 의 대부분이 표적
하나(`1n81A00` +10.00)에서 나왔다. 그것을 빼면 +0.34 다. 즉 **지금 있는 것은
가설이지 증거가 아니다.** 이 코호트가 그 가설을 처음으로 미리 고정한 정책으로
시험한다.

## 2. 앞선 replay 가 닫아 둔 길 — 다시 열지 않는다

```
posterior 되먹임    기여 +0.00 [-0.32, +0.25].  이번 주 분석에 넣지 않는다.
탐색 몫 25%         기여 -0.15.  순손실이다. 넣지 않는다.
비례 배분           greedy 보다 -1.30.  주 알고리즘으로 쓰지 않는다.
```

되먹임은 sentinel 4 개 위에 백본당 평균 1 개의 탐색 관측만 얹히는 조건에서
측정된 값이다. 후보 깊이가 40 이 되면 조건이 달라지므로 **탐색적 보조**로만
다시 본다 (§8).

## 3. 코호트

```
생성원     RFD3 단독. BioEmu 는 이번 confirmatory 에 넣지 않는다.
표적       34 (동결 목록). CATH pilot 중 v2 와 코호트 B 어디에도 안 쓰인 것.
백본       표적당 6
서열       백본당 42
총 folding 34 x 6 x 42 = 8,568
```

**코호트 A(67 표적 pLDDT 순위화) 표적 재사용을 허용한다.** 종점이 다르고
(joint-pass) 백본을 새로 생성하므로 같은 자료의 재분석이 아니다. 다만 ESM-2
표현이 같다는 점을 결과에 명시한다. **코호트 B 는 허용하지 않는다** — 같은
종점을 이미 그 표적에서 측정했다.

길이 필터는 80-400 aa 다(v2 실측 50-386 에 맞춘다).

**비중복 조건 (v1.1 에서 추가, 생성 전).** 같은 PDB 엔트리에서 두 도메인을
쓰지 않고, 쌍대 서열 동일성 30% 이상인 쌍도 쓰지 않는다. 표적 클러스터
부트스트랩이 표적을 독립 단위로 다루므로 이 조건이 없으면 클러스터 수가
실제보다 부풀려진다. 최초 선정에서 `1advA01`/`1advA02` 가 같은 엔트리이고
동일성 0.82 라 걸렸다(630 쌍 중 유일). 사전순 앞인 `1advA01` 을 남겼다.

이 표적들의 CATH superfamily 분류가 로컬에 없어 산출물의 `superfamily` 는
null 이다. 캠페인 러너는 그 필드를 기록만 하고 판단에 쓰지 않으며, 비중복은
superfamily 가 아니라 PDB 엔트리와 서열 동일성으로 보장한다. **superfamily
수준의 비중복은 확인하지 않았다** - 결과에 한계로 적는다.

**도메인 사슬 추출 (v1.2 에서 추가, 생성 전).** CATH pilot 의 PDB 는 분리된
도메인이 아니라 **생물학적 조립체 전체**인 경우가 많다. 실측: 비중복 후보
40 개 중 다사슬이 25 개이고 그중 18 개는 **이종 복합체**다 (`1keeF01` 은
378 잔기와 1058 잔기 사슬을 함께 갖는다). 캠페인 러너의 `design_chain` 은
ATOM 체인이 하나가 아니면 선다.

그래서 도메인 길이와 맞는 사슬 하나만 뽑아 `hier_targets_pdb/` 에 새 PDB 로
쓴다. 좌표는 바꾸지 않는다. 오차 허용은 ±10 잔기다(결손 잔기 때문이며 v2
실측 최대 3). 맞는 사슬이 없는 6 개(`1c8zA00` `1ktuA00` `1l5cA00` `1nr3A00`
`1o8rA00` `3gs9A01`)는 뺀다. 34 표적 중 7 개는 A 가 아닌 사슬을 쓴다.

**따라서 최종 34 표적이고 예비가 0 이다.** 생성 실패가 나오면 표적을 새로
고르지 않고 모자란 채로 보고한다 (§9).

**깊이 42 (v1.3, 생성 전).** v1.2 까지 40 이었다. 두 가지 이유로 42 로 올린다.
(1) 보존도 tier 가 셋인데 40 은 14/13/13 으로 나뉘어 균형이 깨진다. 42 는
14/14/14 다. (2) 더 중요하게, **깊이 확장 파일럿이 42 에서 효과를 잰다.**
파일럿이 검증한 기하와 확증이 돌릴 기하가 다르면 관측한 효과크기가 그대로
옮겨간다고 볼 수 없다. 추가 비용은 408 fold 다.

### 3.1 왜 6 백본인가

백본을 10 에서 6 으로 줄여도 배분이 착취할 원재료는 거의 그대로다. 현
confirmatory 자료에서 백본 수준 "최고-평균" 성공률 격차를 6 개 부분집합으로
재계산하면 7 unit 중 6 개가 93-102% 를 유지한다(`6vqfA00` 만 71%). 같은
계산량이면 **백본보다 독립 표적에 쓰는 것이 낫다** - 지금 문제는 백본 수가
아니라 표적 간 효과 이질성이다.

### 3.2 MSA 를 GPU 로 돈다 (v1.4, 생성 전)

동결 v2 흐름은 MMseqs 를 **CPU** 로 돌린다(`50_full_msa.py:71`,
`USE_GPU=False`). 이 코호트는 **GPU** 로 돈다. 실측 근거:

```
CPU · 4 worker 동시 · uniref90 · max_seqs 3000
  1agrE02 128 aa  4141.7 s  OK
  1advA01 287 aa  6542.3 s  OK
  1af7A01 274 aa  7200.0 s  MSA_INFEASIBLE   <- 클라이언트 상한
  16vpA00 311 aa  7200.0 s  MSA_INFEASIBLE
  1b12B02 211 aa  7200.0 s  MSA_INFEASIBLE
```

5 개 중 3 개가 상한에 걸렸다. 이대로 34 개를 돌리면 절반 이상이
`MSA_INFEASIBLE` 이 되고, 예비가 0 이므로 그만큼 표적이 사라진다.

**무엇을 감수하는가.** MSA 가 달라지면 보존도 마스크가 달라지고 따라서
fixed positions 도 달라진다. 이 코호트의 결과를 v2 의 절대 수확량과 직접
비교하지 않는다는 뜻이다. 그러나 주 비교는 **같은 코호트 안의 정책 대비**
(`greedy_fill - rf_only`)이고 모든 arm 이 같은 후보 풀·같은 마스크를 쓰므로
대비 자체는 영향받지 않는다. 코호트 안에서 일관하면 충분하다.

구현은 `--use-gpu` 옵트인 플래그다. **동결 v2 기본값은 CPU 그대로**이므로
인자를 주지 않는 기존 호출의 동작은 바뀌지 않는다.

## 4. 예산과 집중 여지

```
warm-up    백본당 sentinel 4 개 = 6 x 4 = 24 calls
주 예산    B = 80  ->  배분 가능 56 calls
집중 상한  한 백본에 warm-up 이후 최대 38 개 -> 38/56 = 67.9%
```

현 자료의 35% 보다 훨씬 깊다. B=60·100 은 민감도로만 낸다.

## 5. 알고리즘 — `greedy_frozen`. 전부 여기서 고정한다.

```
1. 백본마다 sentinel 4 개를 백본 안에서 무작위 추출 (seed 별)        -> 24 calls
2. RF 를 warm-up 24 개로 적합. ESM-2 8M 320 차원, 표준화 없음,
   RandomForestRegressor(n_estimators=100, random_state=seed)
3. 백본 posterior mean = (warm-up 통과 수 + 1) / (warm-up 수 + 2)     Beta(1,1)
4. posterior mean 내림차순으로 백본을 정렬. **동점이면 backbone_key
   사전순**으로 깬다 (seed 와 무관하게 결정적)
5. 정렬 순서대로 한 백본씩 **정원까지 꽉 채운다**.
   정원 = min(40, 후보 수) - 4 = 36. 남은 배분량이 정원보다 적으면 그만큼만.
6. 각 백본 안에서는 RF 예측 상위부터 고른다. RF 동점이면 sequence_id
   사전순.
7. 배분량이 소진될 때까지 5-6 을 반복한다.
```

**posterior 갱신 없음. 탐색 몫 없음. 한 번에 한 백본씩 꽉 채운다.**
이것이 "greedy" 의 정의이며 여기서 더 조정하지 않는다.

비교 대상은 모두 **같은 seed 에서 같은 warm-up 표본**을 받는다. arm 간 차이는
남은 56 calls 를 쓰는 방식에서만 생긴다.

```
rf_only          백본 무시. RF 예측 상위 56 개.            <- 주 비교 상대
equal_random     백본에 균등 배분, 백본 안에서 무작위
backbone_only    greedy 배분, 백본 안에서 무작위
mpnn_only        백본 무시. MPNN NLL 오름차순 56 개
oracle           백본 무시. 참 라벨 상위 56 개. 눈금으로만 쓴다
```

## 6. 종점

### 6.1 Primary — 정규화 회수율

unit 마다

```
G(policy) = (Y_policy - Y_equal_random) / (Y_oracle - Y_equal_random)
Primary   = G(greedy_frozen) - G(rf_only)   의 표적 평균
```

이 정규화는 검정력을 위한 변환이 아니라 **"그 표적에서 실제로 회수 가능한
여지 중 얼마를 정책이 가져갔나"** 를 비교하는 것이다. unit 별 joint-pass
기회가 0.02-0.94 로 크게 다르면 개수 차이는 기회 크기에 끌려간다.

### 6.2 분모 자격 규칙 — 결과를 보기 전에 정한다

분모가 0 에 가까우면 비율이 폭발한다(현 자료 `4ai2A02` 분모 0.40). 분모의
기댓값은 닫힌 형태로 나온다.

```
분모(r) = H*r + min(B-H, (N-H)*r) - B*r      N=252, B=80, H=24
```

**분모 >= 5 를 primary 자격으로 한다.** 이 설계에서 자격 구간은
`0.032 <= joint-pass 율 <= 0.910` 이다. 현 설계(pool 180 · warm-up 40)의
`0.050-0.875` 보다 넓다 - 깊은 pool 과 작은 warm-up 이 둘 다 돕는다.

자격 미달 unit 은 **primary 에서 빼되 raw-count secondary 에는 그대로 남긴다.**
자격 판정은 실측 joint-pass 율로 하며, 정책 결과를 보고 판정하지 않는다.

### 6.3 Key secondary — 원시 개수

```
Y(greedy_frozen) - Y(rf_only)  의 표적 평균 (자격 규칙 적용 안 함)
```

효과의 실제 크기를 보여준다. primary 와 방향이 다르면 둘 다 보고한다.

```
            그 외에는 지지하지 않는다. 동등성·비열등성으로 쓰지 않는다.
```

### 7.0 표본 크기를 파일럿 결과로 정한다 (v1.5, 파일럿 결과 전에 동결)

현재 34 표적은 **깊이 18 에서 잰** 효과(정규화 0.118, SD 0.184)로 계산한
값이다. 파일럿이 깊이 42 에서 효과를 다시 재므로, 그 값으로 표본을 정하는
것이 맞다. **파일럿 결과를 보기 전에 공식을 전부 고정한다.**

```
SD_p, D_p = 파일럿(37_) 의 greedy_fill|B80 자격 unit 에서 관측한
            unit 별 D(42) 의 표준편차와 평균
n_req     = max( (2.80 * SD_p / D_p)^2 , 8 )        8 = 동결 min_clusters
n_targets = clamp( ceil(n_req / 0.55), 15, 34 )     0.55 = v2 실측 자격률
```

`0.55` 는 v2 confirmatory RFD3 원 표적 11 개에서 관측한 분모 자격률이고
결과를 보고 바꾸지 않는다. 하한 15 는 min_clusters 8 을 채우는 최소값,
상한 34 는 가용 표적 수다.

**어느 표적을 쓰는지는 결과에 의존하지 않는다.** 이미 동결된 34 개 목록
(`hier_confirmatory_targets.json`, 길이 층화 순서)의 **앞에서부터** n_targets
개를 자른다. 결과를 보고 표적을 고르거나 바꾸지 않는다.

```
D_p <= 0.118  -> 34 표적 · 8,568 fold
D_p  = 0.15   -> 22 표적 · 5,544 fold
D_p >= 0.20   -> 15 표적 · 3,780 fold  (하한)
```

`D_p` 가 0 이하이거나 구간이 0 을 포함하면 이 공식을 쓰지 않는다 - §6 의
게이트에서 이미 멈춘다.

### 7.1 검정력 — 미리 적어 둔다

현 replay 의 정규화 효과(평균 +0.118, 자격 unit SD 0.184)를 그대로 쓰면

```
자격률 55% (원 표적 11 개 실측) -> 34 표적에서 자격 unit 약 18.7
검정력 약 79%,  80% 검정력의 MDE 는 약 +0.12
```

자격률 55% 는 표적 11 개에서 나온 추정이라 불확실하다. 자격 unit 이 16 개
아래로 떨어지면 검정력이 73% 밑이며, 그 경우 **음성 결과를 "효과 없음" 으로
쓰지 않는다** - 결론 문장에 관측된 자격 unit 수와 그때의 검정력을 함께 적는다.

## 8. 탐색 — 판정하지 않는다

깊이 40 에서 처음으로 되먹임을 제대로 볼 수 있다. `adaptive_sentinel`
(탐색 몫 25%, sentinel 관측으로만 posterior 갱신, Thompson sampling) 을
탐색 arm 으로 함께 낸다. **주 판정을 바꾸지 않는다.**

## 9. 하지 않는 것

- 결과를 보고 알고리즘 세부(§5)를 바꾸지 않는다.
- 결과를 보고 표적을 교체하거나 추가하지 않는다. 생성 실패는 실패로 보고한다.
- 분모 자격 문턱 5 를 결과를 보고 바꾸지 않는다.
- EFBC 를 계산하지 않는다. coverage 결론을 내지 않는다.
- BioEmu 를 이 confirmatory 에 넣지 않는다.
- 2.0 A / 85 pLDDT / 0.5 SoluProt 문턱을 바꾸지 않는다.
- 되먹임 arm 의 결과로 주 판정을 바꾸지 않는다.
- 이 결과를 코호트 B·C 의 서열 축 결론과 하나로 합치지 않는다.
