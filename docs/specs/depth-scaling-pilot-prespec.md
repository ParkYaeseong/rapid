# 깊이 확장 파일럿 — 실행 전 사전지정

> **상태: 실행 전 동결.** 이 문서가 커밋된 뒤에 설계·폴딩·분석을 돌린다.
> **확증 분석이 아니다.** 가설을 만든 바로 그 표적을 다시 쓴다.

작성 2026-09-21. 대상: `scripts/transcoder/59_extend_depth_pilot.py`(아직 없음),
`scripts/benchmark/37_depth_scaling.py`(아직 없음).

## 1. 무엇을 묻는가 — 하나다

`36_` 은 `greedy_frozen - rf_only = +1.55 [-0.60, +4.25]` 를 냈다. 0 을 포함하고,
+1.55 의 대부분이 표적 하나(`1n81A00` +10.00)에서 나온다. 그것을 빼면 +0.34 다.

그 결과는 **백본당 후보가 18 개라 한 백본에 배분 예산의 35% 까지만 집중할 수
있는 조건**에서 나왔다. 8,640 fold 확증 코호트(`hierarchical-confirmatory-prespec.md`)
는 "깊이가 허용되면 효과가 커진다" 는 **검증되지 않은 가정**에 서 있다.

> **깊이를 18 에서 42 로 올리면 `greedy_frozen - rf_only` 가 커지는가?**

커지면 확증 코호트의 전제가 확인된다. 안 커지면 그 캠페인을 접고 6,840 fold 를
아낀다. 어느 쪽이든 1,800 fold 로 답이 나온다.

## 2. 깊이와 너비를 동시에 바꾸지 않는다

6 백본으로 줄이면서 깊이를 늘리면 두 가지가 한꺼번에 바뀐다. `36_` 에서
`adaptive_sentinel` 의 세 요인이 뒤섞여 되먹임 효과를 오귀속할 뻔했던 것과
같은 함정이다. **기존 백본을 하나도 버리지 않고 깊이만 올린다.**

```
(10bb, 18)  기존 자료. 추가 비용 0
(10bb, 42)  이번에 만든다
(6bb, 42)   (10bb,42) 의 부분표본. 추가 비용 0. 확증 코호트의 기하와 같다
```

## 3. 코호트 — 새 표적을 만들지 않는다

```
생성원   RFD3 단독
코호트   confirmatory (v2). calibration 은 쓰지 않는다 (freeze §14)
unit     informative 8 개: 1j5uA01 1n81A00 1sdiA00 1x3aA00
                          4ai2A02 4ifxA00 4wexA00 6vqfA00
백본     기존 것 전부. 7 unit x 10 + 4ai2A02 5 = 75
깊이     18 -> 42 (백본당 +24)
추가 fold 75 x 24 = 1,800
```

**새 backbone 을 만들지 않고 MSA 를 다시 돌리지 않는다.** 보존도는 동결된
`full_msa_manifest.json` 을 그대로 쓴다.

### 3.1 왜 42 인가

현재 tier 구성이 백본당 정확히 6/6/6 이다. 40 으로 가면 14/13/13 이 되어
보존도 균형이 깨진다. 42 는 14/14/14 로 균형을 유지하고 추가 비용은 94 fold
뿐이다. **tier 당 +8 을 만든다.**

### 3.2 집중 여지가 어떻게 변하는가

B=80 · warm-up 4/백본 기준:

```
10 백본 · 깊이 18   warm-up 40 · adaptive 40 · 한 백본 최대 +14 -> 35%
10 백본 · 깊이 42   warm-up 40 · adaptive 40 · 한 백본 최대 +38 -> 95%
 5 백본 · 깊이 42   warm-up 20 · adaptive 60 · 한 백본 최대 +38 -> 63%  (4ai2A02)
```

## 5. 분석 — 주 비교 하나

### 5.0 v1.1 정정 — 두 greedy 가 서로 다른 알고리즘이었다

동결 문서를 대조하다 불일치를 찾았다. **폴딩 전에 적어 둔다.**

```
36_ 이 측정한 greedy_frozen        고정 posterior 에서 **Thompson 추출**.
                                   매 호출마다 theta_b ~ Beta 를 뽑아 argmax.
                                   확률적이고 seed 에 의존한다.
확증 사전지정 §5 가 동결한 것       posterior **mean 내림차순**으로 정렬해
                                   한 백본씩 정원까지 채운다. 결정적이다.
```

캠페인을 정당화한 `+1.55` 는 **Thompson 쪽**에서 나왔는데 확증 코호트는
결정적 쪽을 동결했다. 둘은 다른 정책이다. 추가 폴딩 없이 둘 다 잴 수 있으므로
둘 다 낸다.

```
greedy_fill       결정적. 확증 사전지정 §5 그대로.   <- 파일럿 **주** 대상
greedy_thompson   Thompson. 36_ 과 같다.            <- 연속성 확인용 보조
```

주 판정은 `greedy_fill` 로 한다 - 확증 코호트가 실제로 돌릴 알고리즘이기
때문이다. `greedy_thompson` 은 36_ 의 +1.55 가 재현되는지 보는 용도이며,
두 arm 의 깊이 반응이 갈리면 그 자체를 보고한다.

### 5.1 재생 절차

unit 마다 두 깊이에서 위 두 greedy 와 `rf_only` 를 재생한다. warm-up·ceiling·
RF 규격은 `hierarchical-confirmatory-prespec.md` §5 를 그대로 쓴다. 여기서
알고리즘을 다시 손대지 않는다.

```
G(policy, d) = (Y_policy - Y_equal) / (Y_oracle - Y_equal)   깊이 d 에서
D(d)         = G(greedy_fill, d) - G(rf_only, d)      (주)
D_th(d)      = G(greedy_thompson, d) - G(rf_only, d)  (보조)
주 비교      = D(42) - D(18)   의 unit 평균
```

깊이 18 집합은 **기존 18 개 그대로**이고 깊이 42 집합은 그것을 포함한다.
즉 중첩 설계이며 unit 안에서 쌍을 이룬다.

```
예산       B=80 (주). B=60·100 은 민감도
seed       42 · 123 · 7 · 2024 · 31337
구간       unit 클러스터 부트스트랩 2,000 회 · seed 20260921
분모 자격  깊이 42 에서 oracle-equal >= 5 (확증 사전지정 §6.2 와 같은 규칙)
원시 개수  key secondary 로 함께 낸다
```

## 6. 판정 규칙 — 결과를 보기 전에 정한다

```
D(42)-D(18) 이 양수이고 0 제외   깊이 가정이 확인된다. 확증 코호트를 돌린다.
D(42)-D(18) 이 0 포함            확인되지 않는다. D(42) 의 크기와 부호를
                                 함께 보고 확증 코호트 실행 여부를 사람이
                                 판단한다. 자동으로 돌리지 않는다.
D(42)-D(18) 이 음수이고 0 제외   깊이를 늘려도 나빠진다. 확증 코호트를
                                 접는다.
```

**unit 이 8 개뿐이라 검정력이 낮다.** `36_` 의 SD 를 그대로 쓰면 n=8 에서
80% 검정력의 MDE 는 정규화 척도로 약 +0.19 다. 즉 **작은 증가는 못 잡는다.**
음성이 나와도 "깊이 효과 없음" 으로 쓰지 않고, 관측된 점추정과 구간을 그대로
적는다.

## 7. 하지 않는 것

- 이것을 confirmatory 라 부르지 않는다. 가설을 만든 표적을 다시 쓴다.
- 이 결과로 `warmup_informed - rf_only` 주 판정(`35_`)을 바꾸지 않는다.
- 새 표적·새 백본·새 MSA 를 만들지 않는다.
- 알고리즘 세부를 다시 조정하지 않는다.
- 되먹임 arm 을 주 비교에 넣지 않는다.
- EFBC 를 계산하지 않는다. calibration 코호트를 쓰지 않는다.
- 동결된 v2 산출물을 덮어쓰지 않는다.
- 중복 제거로 줄어든 후보를 재시도로 채우지 않는다.
